# MOX MVP — SPEC

## 1. Demo story (what the video must show, in order)
1. Login → Dashboard after scanning `demo_target/` (real counts, real scan time).
2. Work queue ranked by risk, each row with a verdict chip MIGRATE / CONTAIN / ACCEPT.
3. Asset detail: one key found in several places = ONE asset; score breakdown; verdict; PQC replacement.
4. Fix: diff preview → Approve → patch with backup → automatic re-scan → "finding cleared".
5. Export CycloneDX CBOM (shows "schema valid"). 5-wave roadmap.
6. Attest: what leaves vs what never leaves, JSON preview, self-check, export signed attestation.
7. NCIIPC Sector view built only from signed attestations (simulated, labelled demo data).

## 2. Layout
```
mox/            scanner, planes/, correlate.py, score.py, verdict.py, fixers/, cbom.py,
                attest.py, auth.py, db.py, api.py, cli.py (python -m mox ...)
data/           nist_status.json (given), rules.json (detection patterns), keys/ (runtime)
demo_target/    generated by `python -m mox make-demo` (never hand-edit)
web/            React app
tests/          pytest
```
SQLite file: `data/mox.db` (tables: scans, findings, assets, asset_locations, fixes, audit, users).

## 3. Demo target — `python -m mox make-demo`
Create a realistic legacy app "gov-portal-legacy" covering all 7 planes (synthetic, safe):
- **code**: `auth/token_signer.py` (loads `certs/api-gw.key`, RSA PKCS#1 v1.5 sign),
  `auth/passwords.py` (hashlib.md5), `payments/Crypto.java` (SHA-1, RSA 2048 KeyPairGenerator,
  DES Cipher), `web/sign.js` (createHash('md5'), createSign('RSA-SHA256')),
  `utils/legacy_aes.py` (AES.MODE_ECB), `services/ecdsa.go` (ecdsa P-256).
- **dependencies**: requirements.txt (pycryptodome, cryptography), package.json (node-forge,
  jsonwebtoken), pom.xml (bcprov-jdk15on).
- **configs**: `conf/nginx.conf` (ssl_protocols TLSv1 TLSv1.1 TLSv1.2; ssl_ciphers incl. DES-CBC3-SHA;
  ssl_certificate certs/api-gw.crt; ssl_certificate_key certs/api-gw.key);
  `conf/nginx-edge.conf` with `ssl_ecdh_curve X25519MLKEM768:X25519` (real hybrid);
  `conf/java.security`; `infra/kms.tf` (key_spec = "RSA_2048").
- **certificates & keys** (generate with `cryptography`, fresh each run): api-gw RSA-2048 key + cert;
  the SAME key also inside `keystore/app.p12`; internal-ca RSA-4096; legacy RSA-1024 cert (expired);
  ECDSA P-256 cert.
- **binaries**: `vendor/sync-agent.bin` — synthetic blob containing strings `RSA_generate_key`,
  `MD5_Init`, `OpenSSL 1.1.1k` (clearly marked synthetic in a README inside demo_target).
- **containers**: `Dockerfile` (FROM an old base, installs openssl 1.1.1) + `image/app-image.tar`
  in docker-save layout with one layer containing a copy of `api-gw.crt`.
- **TLS endpoint**: `python -m mox demo-tls` serves api-gw cert on 127.0.0.1:8443 (for the live probe).

## 4. Scanner — 7 planes (`mox/planes/*.py`, one plugin each, common Finding model)
Finding: plane, algorithm, key_size, mode, file, line, evidence (snippet ≤120 chars), fingerprint?,
confidence (high|medium|low), detector.
- code (.py .java .js .ts .go .c .cs): regex/AST rules from data/rules.json; key size read from the
  MATCHED LINE; dedupe by (file,line,algorithm); skip import/comment-only lines; detect ECB mode,
  3DES/TripleDES, AES.new(..., AES.MODE_ECB).
- dependencies: known crypto libs + versions → low confidence (usage not proven).
- binaries: strings scan of non-text files → low/medium.
- configs: nginx/apache/openssl/java.security/terraform → protocols, ciphers, curves, key specs.
- certificates & keys: PEM/DER/PKCS#12 via `cryptography` → algorithm, size, sig alg, expiry,
  SPKI SHA-256 fingerprint → high confidence. Never persist the private key.
- containers: parse docker-save tar, extract layers to temp, re-run the other planes, tag plane=containers.
- tls: `--probe host:port` handshake via ssl → protocol, cipher, peer cert fingerprint → high.
Confidence: live TLS / parsed cert = high; explicit crypto API call = medium; dependency/string = low.
Low-confidence findings go to a "Verify first" list, not the main queue.

## 5. NIST table (`data/nist_status.json`, given — read it, never hard-code statuses)
Lookup by algorithm + key size/curve/mode. Fields: now, after_2030, after_2035, quantum_vulnerable,
legacy_use, source, notes. If an entry is missing → status "unknown" (+ note), don't guess.

## 6. Correlation (`correlate.py`)
Group findings into ASSETS: same SPKI fingerprint (key file, cert, p12, TLS peer cert, container copy)
= one asset. Also attach config/code findings that reference that key/cert file path.
Asset shows "N findings → 1 asset" and all locations. Findings without a fingerprint = own asset.

## 7. Scoring (`score.py`) — explainable, every term stored
- base from NIST `now`: disallowed 40, deprecated 25, approved 5, unknown 15.
- quantum_vulnerable: +25 (halve this term if a REAL hybrid is present on that asset, e.g. X25519MLKEM768
  group on the same endpoint — co-occurrence in a file is NOT hybrid).
- Mosca per asset: X = data shelf-life years (rules by path/tag: auth|token|citizen|payments 15,
  default 7, test|log|tmp 1; editable per asset in UI), Y = migration years by coupling
  (config 1, source 2, library 3, vendor binary 5, firmware/HSM/KMS 6), Z = threat horizon
  (project setting, default 10). exposure = X+Y-Z; if >0 add min(25, 3*exposure).
- business criticality 1|2|3 (defaults by path; editable) → multiplier 0.8 / 1.0 / 1.2.
- confidence multiplier high 1.0, medium 0.85, low 0.6.
- floor: NIST `now` = disallowed and used for protection → score ≥ 70.
- clamp 0–100. Tier: ≥70 Critical, ≥50 High, ≥30 Medium, else Low.
- store and show the breakdown ("why this score").

## 8. Verdicts + recommendations (`verdict.py`)
- CONTAIN: coupling in {vendor binary, firmware/HSM/KMS} or no source to patch → recommend
  segmentation, crypto-agile gateway, shorter key lifetime.
- ACCEPT: score < 30 or X ≤ 1.
- MIGRATE: everything else that is weak or quantum-vulnerable.
- Replacement map: RSA/ECDSA signatures → ML-DSA-65 (hybrid first); RSA/ECDH/DH key exchange →
  ML-KEM-768 (X25519MLKEM768 hybrid); MD5/SHA-1 → SHA-256; DES/3DES/ECB → AES-256-GCM;
  TLS < 1.2 → TLS 1.2+/1.3. Show size/latency note (ML-KEM-768 pk 1,184 B; ML-DSA-65 sig 3,309 B).
- Assign migration wave 1–5 from tier + exposure.

## 9. Fix-and-verify (`fixers/`)
Fixers (text-safe, deterministic): md5/sha1 → sha256 (py/js/java); RSA keygen 1024/2048 → 3072 with
comment "interim: plan ML-DSA-65 hybrid"; nginx: drop TLSv1/TLSv1.1, remove DES-CBC3-SHA, add
`ssl_ecdh_curve X25519MLKEM768:X25519`. Flow: preview unified diff → approve → write `.bak` backup →
apply → re-scan only that file → mark finding cleared or still present. Every step → audit log.

## 10. CBOM (`cbom.py`)
CycloneDX 1.6 JSON, components type "cryptographic-asset" with valid cryptoProperties
(assetType algorithm|certificate|related-crypto-material|protocol; algorithmProperties.primitive
must be a valid enum e.g. pke, signature, hash, kem, block-cipher, ae, key-agree). Extra fields as
properties "mox:*" (nist now/2030/2035, score, tier, verdict, wave, confidence, locations count).
Validate with cyclonedx-python-lib JSON validator; UI shows "schema valid".

## 11. Attestation + sector view (`attest.py`)
- Operator Ed25519 key generated on first run in data/keys/ (never exported).
- Attestation JSON (only counts/proofs): schema "mox.attestation/v1", sector, scan_date,
  coverage {planes, files}, assets {total, hndl_exposed, quantum_vulnerable, safe_or_out_of_scope},
  verdicts {migrate, contain, accept}, readiness_index 0–100, hybrid_pq_count, cbom_merkle_root
  (SHA-256 Merkle over sorted component hashes), scanner version, signature {alg, key_id, sig}.
- Self-check before export: root re-derived, no field contains a path/host/IP, signature verifies.
- `python -m mox demo-attestations` makes simulated signed attestations for 6 sectors
  (power, telecom, government, banking, transport, strategic). Sector view verifies signatures,
  aggregates, ranks "if RSA-2048 falls" by HNDL-exposed. Banner: "simulated attestations · demo data".

## 12. Auth + audit
Argon2id passwords; `python -m mox create-admin` (no public admin sign-up; role never from request);
JWT in httpOnly cookie; secret from env MOX_SECRET or generated once into data/keys/secret (32+ bytes);
uvicorn without debug. Audit table: login ok/failed, scan, fix preview/approve/apply, cbom export,
attestation export.

## 13. API (FastAPI, /api/*)
auth/login, auth/logout, auth/me · scans (POST start {path, probe?}, GET latest) · assets (list,
detail) · settings (threat horizon) · fixes (preview, approve+apply) · cbom (export, download) ·
roadmap · attest (preview, export) · sectors (aggregate demo) · audit.

## 14. UI (dark theme — match docs/mockups/ui.css + reference PNGs)
Screens: Login · Dashboard (KPI cards: files, planes, scan time, assets, HNDL-exposed,
quantum-vulnerable, safe, hybrid; risk field scatter x=exposure years, y=criticality; verdict split
bar) · Work queue (sorted, verdict chips, tier, confidence, "Verify first" tab) · Asset detail
(locations graph "N → 1", score breakdown, NIST now/2030/2035, verdict, replacement, what breaks =
other locations) · Fix (diff, approve, re-scan result) · CBOM (export + valid badge) · Roadmap
(5 waves: Discover, Prioritise, Agility-engineer, Hybrid deploy, Validate & attest) · Attest
(leaves / never leaves, JSON preview, self-check) · Sector view · Audit log. Header chip:
"Offline — 0 outbound calls".

## 15. CLI
`python -m mox make-demo | demo-tls | scan <path> [--probe host:port] | create-admin |
demo-attestations | bench <path...>`. `bench` prints: files scanned, seconds, planes hit, findings,
assets, quantum-vulnerable, HNDL-exposed, verdict split. These numbers go in our slides.

## 16. Tests (pytest)
key size per line (RSA-1024 vs 4096 in one file) · dedupe · import/comment skip · correlation
(key + cert + p12 + nginx ref → 1 asset) · Mosca per asset · disallowed floor ≥70 · hybrid only when
real · verdict rules · NIST lookup incl. RSA-3072 after_2030 = approved · CBOM schema valid ·
attestation has no path/host and signature verifies · fixer diff + re-scan clears finding ·
no public admin registration.
